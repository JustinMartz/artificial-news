Spring Boot — Keep the database password out of Git

Three simple, idiomatic approaches for local development and production. Use environment variables for most cases; use a secret manager for production.

1. Environment variables (recommended)

Reference env vars from application.properties so no secrets are checked into Git.

# src/main/resources/application.properties
spring.datasource.url=jdbc:postgresql://localhost:5432/artificial_news
spring.datasource.username=${DB_USER}
spring.datasource.password=${DB_PASS}

Set the variables locally before running:

# macOS / Linux (bash/zsh)
export DB_USER=artificial_user
export DB_PASS='superStrongPassword'

# Run
./mvnw spring-boot:run
# or
DB_USER=artificial_user DB_PASS=superStrongPassword java -jar app.jar

2. Local-only application-local.properties

Use Spring profiles and keep a local-only properties file out of version control.

# Add to .gitignore
src/main/resources/application-local.properties

# application-local.properties (not checked in)
spring.datasource.username=artificial_user
spring.datasource.password=superStrongPassword

# Run with the local profile
SPRING_PROFILES_ACTIVE=local ./mvnw spring-boot:run

3. .env file + dotenv (convenient for dev)

Create a .env file and add it to .gitignore. Use a dotenv loader if you want automatic loading.

# .env (DO NOT commit this file)
DB_USER=artificial_user
DB_PASS=superStrongPassword

# Ensure .env is ignored
# .gitignore
.env

You can use a small Java library (e.g. io.github.cdimascio:dotenv-java) or a Spring Boot plugin to load .env during local development.

Production: use a real secret manager

For production environments use dedicated secret stores:

  • AWS Secrets Manager, Azure Key Vault, or GCP Secret Manager
  • HashiCorp Vault
  • Docker/Kubernetes secrets

These integrate with your deployment system and avoid storing long-lived secrets in your repository. Local development can still use env vars or application-local.properties.

Recommended minimal setup (simple + safe)

  1. Use application.properties that references env vars:
# src/main/resources/application.properties
spring.datasource.url=jdbc:postgresql://localhost:5432/artificial_news
spring.datasource.username=${DB_USER}
spring.datasource.password=${DB_PASS}
  1. Create a local .env or export DB_USER / DB_PASS in your shell.
  2. Add .env and any local-only config files to .gitignore.

src/main/resources/application-local.properties
